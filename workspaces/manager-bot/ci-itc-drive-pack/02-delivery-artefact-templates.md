# ITC Delivery Artefact Templates

## RAID Log

Use for risks, assumptions, issues, and dependencies.

| ID | Type | Description | Impact | Probability | Owner | Mitigation / Action | Due Date | Status | Last Updated |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| RAID-001 | Risk |  | High / Medium / Low | High / Medium / Low |  |  |  | Open |  |

Minimum rules:
- Every item has an owner.
- Every open item has a next action.
- High risks/issues are reviewed weekly.
- Closed items retain closure reason and date.

| ACT-001 |  |  |  |  | High / Medium / Low | Open |  |  |

- No action should exist without owner and due date.
- Overdue actions are escalated in the next governance forum.
- Closed actions include evidence or outcome.

## Dependency Tracker

| ID | Dependency | Needed By | Depends On | Owner | Impact If Missed | Status | Escalation Path | Last Updated |

| DEP-001 |  |  |  |  |  | Open |  |  |

Minimum rules:
- Every dependency has a need-by date and named owner.
- Dependencies close only when the receiving team confirms the dependency is satisfied.
- Blocked dependencies should appear in the RAID log.

## Sprint Retrospective Action Log

| Sprint | Theme | Improvement Action | Owner | Due Date | Success Measure | Status | Review Notes |
| --- | --- | --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  | Open |  |

Minimum rules:
- Select a small number of meaningful actions per retrospective.
- Review previous actions at the start of the next retrospective.
- Track repeated themes to identify systemic blockers.

## Sprint Review Evidence Checklist

- Sprint goal stated.
- Completed items demonstrated.
- Deferred or incomplete items explained.
- Stakeholder feedback captured.
- Decisions and actions logged.
- Follow-up owners and due dates assigned.
